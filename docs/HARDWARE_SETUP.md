# Hardware setup and troubleshooting

Start with SimLab, then attach one device at a time to a dedicated Agent host. Lab Platform does
not install drivers, modify udev rules, add users to groups, bring up CAN interfaces, or change USB
permissions. Make those host changes explicitly, review them locally, and restart the Agent after
permissions change.

The compatibility matrix, not device discovery alone, defines support. Check
[hardware compatibility](HARDWARE_COMPATIBILITY.md) before relying on a combination in CI.

## Preflight

1. Record the Agent host OS and architecture.
2. Connect one known-good USB data cable and avoid unpowered hubs for the first probe.
3. Identify devices without guessing:

   ```console
   python -m serial.tools.list_ports -v
   # Linux, if installed:
   lsusb
   # macOS:
   system_profiler SPUSBDataType
   ```

4. Run external-tool version checks as the same user that runs the Agent.
5. Use a stable serial number or explicit port. A VID/PID pair alone can match multiple devices.
6. Start the Agent and inspect diagnostics before reserving hardware:

   ```console
   lab-agent doctor --config-dir config
   labctl plugin list
   labctl plugin doctor <plugin>
   ```

Never run the Agent as root to bypass a permission error. Grant the narrow device access required
by a dedicated service account.

## ESP32 reference target

The canonical minimal physical setup is an ESP32 DevKit V1 over USB. Copy
[`examples/esp32-local.yaml`](../examples/esp32-local.yaml), set its stable serial selector, and
follow [the ESP32 setup](ESP32_SETUP.md). The final capability is named `flash`; `firmware` remains
a temporary input alias for pre-1.0 clients.

Required physical evidence is probe, flash with checksum verification, boot serial through
`READY`, reset, repeat probe, and safe cleanup after cancellation or disconnect.

## STM32 with ST-Link and OpenOCD

Install OpenOCD using the host's trusted package mechanism and verify it as the Agent user:

```console
openocd --version
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
  -c "transport select swd" -c "init; targets; shutdown"
```

The direct command is a host preflight only. Normal operations use the plugin/target adapter with
a fixed argument vector and timeout. A minimal bench fragment for a Nucleo-F446RE is:

```yaml
hardware:
  benches:
    - id: stm32-nucleo-f446re-01
      name: STM32 Nucleo F446RE
      target_type: stm32
      labels: {board: nucleo-f446re, debugger: st-link}
      connection:
        serial_port: auto
        baud_rate: 115200
        usb: {serial_number: "<stable-ST-Link-serial>"}
      openocd:
        executable: openocd
        interface_config: interface/stlink.cfg
        target_config: target/stm32f4x.cfg
        transport: swd
        timeout_seconds: 120
```

OpenOCD configuration names must not contain command separators. Flash artifacts must be regular
files within the Agent's artifact flow; workflow input cannot inject OpenOCD commands.

Typical failures:

| Observation | Check | Safe response |
| --- | --- | --- |
| executable missing | `openocd --version` under the service account | Install/pin OpenOCD or fix the service `PATH`. |
| probe not found | cable, `lsusb`/System Information, ST-Link firmware | Reconnect, remove a conflicting debugger process, then re-probe. |
| permission denied | device ownership and service-account groups | Apply a reviewed host rule and log in/restart the service. |
| target halted or wrong ID | exact Nucleo model and target config | Use the correct OpenOCD target file; do not force an unknown target. |
| serial works but debug fails | USB composite interfaces and cable | Check that both debug and serial functions enumerated. |

## J-Link

Install SEGGER tooling separately and accept its license. Record the exact J-Link software,
firmware, probe model, target device name, interface, and speed in evidence:

```console
JLinkExe -device nRF52840_xxAA -if SWD -speed 4000
```

J-Link command files are generated by the adapter, not accepted as arbitrary workflow text. A
J-Link integration can pass the official tool contract where tooling is available, but the matrix
stays `EXPERIMENTAL` until a real target run is attached.

## RP2040

Two common paths are picotool over USB or a UF2 mass-storage volume. Confirm the board is in the
intended boot mode and pin `picotool` when using it:

```console
picotool version
picotool info
```

UF2 copy is not successful until the artifact was validated before copy, the copy completed, and
the expected device re-enumerated. Never select the first removable volume or derive a mount path
from workflow input. RP2040 configuration/SDK presence does not imply a verified physical path;
consult the matrix.

## Nordic nRF52

Use either a pinned `nrfjprog` installation or the reviewed J-Link path. Confirm the exact family
and connected probe before any erase or program command:

```console
nrfjprog --version
nrfjprog --ids
```

Chip erase and protection recovery are destructive maintenance actions and must not be implicit
workflow retries. Keep them outside ordinary `flash` unless explicitly reviewed and authorized.

## Independent USB relay power

A relay channel is an independent resource, not a hidden target property. Give each physical
channel a stable resource ID, bind it to a bench, and reserve/lock it with the target. A command
transport is configured as a fixed argument template containing only `{channel}` and `{state}`;
the channel accepts letters, digits, `.`, `_`, and `-`.

Validate with a disconnected load first, then a current-limited target:

1. `off()` and `on()` are idempotent.
2. Cycling channel 1 never changes channel 2.
3. A second bench cannot acquire the same exclusive channel.
4. Cancellation leaves a documented safe state.
5. Unplug is reported as unavailable, not as a successful state change.

Do not switch mains voltage with the reference USB-relay integration.

## SocketCAN

Linux SocketCAN setup is host administration. Example for an already reviewed `can0` interface:

```console
ip -details link show can0
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
```

Do not copy those commands into an unattended Agent bootstrap without validating the adapter,
bitrate, bus termination, and service ownership. The plugin opens an existing allowed interface;
workflow inputs cannot name arbitrary network interfaces.

Physical evidence covers standard and extended frames, filters, receive cancellation/timeouts,
interface disappearance/recovery, and a raw CAN artifact such as PCAP. Use a terminated isolated
test bus; never connect an unreviewed workflow to a vehicle or production control network.

## Instruments and captures

Treat scopes, logic analyzers, power meters, and SCPI devices as independent resources. Pin the
vendor/transport library, whitelist commands for ordinary workflows, enforce acquisition timeout
and size limits, and preserve raw or standard files plus metadata. Screenshots are useful previews
but are not the only capture artifact.

For TCP instruments, use an allowlisted configured address; never accept an arbitrary URL or host
from workflow input. For USB instruments, apply the same stable identity and permission rules as
debug probes.

## Resource conflicts and recovery

One composed bench may bind a target, serial adapter, power channel, debugger, CAN interface, and
instrument. The Phase 9 resource coordinator can acquire all required locks atomically and reject
`RESOURCE_CONFLICT` in its contract-tested path. The durable control-plane reservation flow is not
yet connected to that coordinator, so shared physical resources must not be treated as safely
multi-bench in a production deployment until readiness criteria 12 and 13 are closed. Do not
delete lock records or unplug shared equipment to bypass coordination.

After a process crash or disconnect, re-probe every affected resource and run a non-destructive
health operation before reuse. Resource-lock crash recovery still requires release evidence and
production-flow integration. An uncertain flash or power result must never be retried
automatically without a fresh ownership check.

## Collecting evidence

Attach redacted configuration, diagnostics, tool versions, workflow/result IDs, artifact hashes,
and the negative-path outcome to the compatibility row. The Phase 9 release gate and evidence
format are documented in [readiness](PHASE_9_READINESS.md) and
[reliability validation](RELIABILITY_VALIDATION.md).
